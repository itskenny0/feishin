# iOS (Capacitor)

A Capacitor-based wrapper that runs the existing `pnpm build:web` bundle inside
an iOS `WKWebView`. The renderer is the same one the Android app and the web
build use — the mobile shell (bottom tab bar, fullscreen player, safe-area
handling) renders on iOS exactly as it does on Android.

The iOS project uses **Swift Package Manager**, not CocoaPods — there is no
`Podfile`, and CI needs only Xcode (no `pod install`).

## Install the prebuilt IPA (sideloading)

The released `.ipa` is **unsigned** — it carries no Apple Developer signature,
exactly like the unsigned Android debug APK. iOS will not install it directly;
you re-sign it on install with one of:

1. Grab the latest `feishin-*-ios-unsigned.ipa` from the
   [Releases page](https://github.com/itskenny0/feishin/releases).
2. Install it with whichever sideloading route fits your device:
   - **AltStore / SideStore** — re-signs with a free Apple ID. App expires
     after 7 days (free account) and must be refreshed; 3-app limit.
   - **Sideloadly** — desktop tool; free Apple ID (7-day) or paid account
     (1-year) signing.
   - **TrollStore** — permanent install, but only on iOS versions with a
     supported install exploit.
   - A paid **Apple Developer** account / MDM if you have one.

A free Apple ID limits you to a 7-day signature; a paid Apple Developer account
extends it to a year. None of that affects the build — it's all done at sign /
install time on your side.

## Build locally

Building an `.ipa` requires **macOS with Xcode** (iOS apps cannot be compiled on
Linux or Windows). You also need `pnpm` and Node 22.

From the repo root:

```bash
pnpm install
pnpm ios:sync     # build:web + stub settings.js + cap sync ios (writes Package.swift)
pnpm ios:open     # open ios/App in Xcode
```

Then in Xcode pick the `App` scheme and Run on a simulator or device. To make a
device build you'll need to set your own signing team under
**Signing & Capabilities** (the CI build is unsigned).

To reproduce the CI's unsigned archive from the command line:

```bash
xcodebuild -project ios/App/App.xcodeproj -scheme App -configuration Release \
  -destination 'generic/platform=iOS' -archivePath build/App.xcarchive \
  CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO CODE_SIGN_IDENTITY="" archive
# then zip Products/Applications/App.app inside a Payload/ folder as the .ipa
```

> `ios/App/CapApp-SPM/Package.swift` is **gitignored** because it embeds
> machine-specific pnpm store paths and is regenerated by `npx cap sync ios`.
> Always run `pnpm ios:sync` (or `npx cap sync ios`) after a fresh checkout /
> dependency change before opening Xcode, or the SPM package won't resolve.

## Releasing

Pushing a fork tag (`v<ver>-itskenny0-YYYY.MM.DD-HHMM`) triggers
`.github/workflows/release-ios.yml`, which builds the unsigned `.ipa` on a macOS
runner and uploads it to the same GitHub Release as the desktop and Android
artifacts. You can also re-run it from the Actions UI against an existing tag
("Run workflow"). See the bottom of that workflow for how to switch to a signed
export if you add an Apple Developer account + signing secrets.

## iOS specifics

- **Background audio**: enabled. `AppDelegate.swift` configures an
  `AVAudioSession` `.playback` category and the app declares the `audio`
  `UIBackgroundMode`, so playback continues when the app is backgrounded or the
  screen locks. Lock-screen / Control Center transport controls come from the
  Web `navigator.mediaSession` hook (`use-media-session.ts`), which WKWebView
  supports.
- **HTTP and HTTPS servers both work**: `NSAppTransportSecurity →
  NSAllowsArbitraryLoads` (in `Info.plist`) is the iOS analogue of Android's
  `usesCleartextTraffic` / `allowMixedContent`, so plain-HTTP Jellyfin /
  Navidrome / Subsonic servers on the LAN load correctly. Public HTTPS
  deployments are unaffected.
- **Local network prompt**: on first connection to a server by LAN IP, iOS
  shows a "find devices on local network" prompt (explained by
  `NSLocalNetworkUsageDescription`). Allow it for LAN servers to work.
- **The Android media-session plugin is not part of the iOS build**:
  `@jofr/capacitor-media-session` is Android-only (foreground service +
  `MediaSessionCompat`). On iOS the Web Media Session API + `AVAudioSession`
  cover the same ground, and the renderer gates the Android plugin hook to
  Android so it never double-wires `navigator.mediaSession`.
- **Electron-only features fall back to the web path**: the MPV audio engine,
  native menus, OS cache directories, etc. are gated on `isElectron()`, which is
  `false` inside the WebView, so the web fallbacks (web audio player, in-app
  menus, idb-keyval, …) are used — same as the Android build.

## Known limitations

- **App icon / splash use the Capacitor template art** until a follow-up runs
  `@capacitor/assets` on a Mac to generate the iOS icon set from the source
  artwork.
- **Unsigned only**: the released IPA must be sideloaded (see above). Signed /
  App Store distribution requires an Apple Developer account and the signing
  secrets documented in `release-ios.yml`.
